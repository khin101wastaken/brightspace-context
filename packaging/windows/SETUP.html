WINDOWS PREVIEW · NYU · CHROME

Your courses, ready for context.

Node and the companion are included. You do not need to install developer tools or run shell commands.

1. Start the companion

Open Brightspace Context Companion from the Start menu. Keep its window open. It displays a pairing code; closing the window stops the companion. Starting another copy will report that the port is already in use.

2. Add the Chrome extension

  1. In Chrome, open chrome://extensions and turn on Developer mode.
  2. Click Load unpacked and select this installed folder:
    app\extension (inside this installation)
  3. Sign into NYU Brightspace in the same Chrome profile.
  4. Open the extension, enter the code from the companion window, and choose Connect.

The extension is installed manually in this preview. The installer does not change Chrome policy, read your school password, or configure ChatGPT automatically.

3. Connect a desktop MCP client

In your supported desktop client's MCP settings, add a STDIO server named brightspace-context. Use these absolute paths:

Command:

runtime\node.exe (inside this installation)

Argument:

app\mcp\start.js (inside this installation)

Equivalent JSON configuration:

Restart the MCP connection as required by your client. The host must support reading original PDF/PPTX/DOCX bytes through MCP resources. Normal retrieval returns a resource link and creates no plaintext file path.
If your client requires a local file, explicitly enable Settings → Temporary file exports in the extension, then request export_document. These optional copies are unencrypted, expire after 15 minutes, and are removed on normal companion shutdown. A crash can leave them until the companion starts again. Exports are disabled by default.


4. Check one reading
Open Resources in the extension, select a semester and click Sync semester. Then ask your connected chat to find one uncached course PDF, request it with request_document, wait for it to be ready, and read its contents. Keep Chrome signed in and the companion running.


Updates and uninstall
Close the companion window and stop its desktop MCP connection before installing an update. Keep the extension loaded from this installation's stable folder; reload it in Chrome after updating and restart MCP. The first updated companion start migrates recognized legacy files to encrypted storage and verifies the copies before retiring plaintext originals. Use Windows Installed apps → Brightspace Context → Uninstall to remove the application and shortcuts.
Uninstall preserves the encrypted cache, pairing and Windows-protected key in %USERPROFILE%\BrightspaceContext\cache. Keep these files and the original Windows profile for recovery. Remove the extension and desktop MCP entry separately. To erase local companion data, stop the companion and explicitly remove the cache directory. Ordinary Downloads are separate and remain where you saved them.
Protected storage
Persistent companion data is encrypted with a key protected by your Windows account. Saved browser catalogs are encrypted too; after a browser restart, start the companion to unlock them without entering another pairing code. Without pairing, newly synced browser catalogs last only for that browser session. If an older cache cannot be migrated or unlocked, preserve it and resolve the reported problem; do not reset or replace its key.


Troubleshooting
The companion window shows timestamped connection, catalog, cache and retrieval events. For more detail, stop the companion and open Brightspace Context → Troubleshooting → Companion (verbose logs) from the Start menu. Verbose mode adds local request status codes and timings. Keep only one companion instance running.


This is an unsigned Windows x64 preview. Tray controls, automatic startup, automatic updates, Chrome Web Store installation, and Mac/Linux packages are future steps. HTML downloads save the document itself; their linked assets are not packaged.
